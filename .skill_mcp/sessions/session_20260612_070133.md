# 项目架构说明

本项目基于现代化的前端技术栈构建，核心框架选用**React**并全面采用*TypeScript*进行类型约束。这种组合不仅保证了开发时的高效体验，还通过静态类型检查显著降低了运行时错误的发生率。配合 Vite 或 Webpack 等构建工具，我们实现了模块化开发和热更新（HMR），从而大幅提升开发迭代效率。

### 性能指标
| 指标 | 数值 | 状态 |
|------|------|------|
| 首屏 (FCP) | 1.2s | 优 |
| 交互时间 (TTI) | 2.5s | 良 |

针对首屏加载速度，我们采用了服务端渲染（SSR）结合静态站点生成（SSG）的策略，确保关键资源优先加载。通过代码分割（Code Splitting）和路由懒加载技术，将初始包体积控制在 150KB 以内。此外，利用 Service Worker 进行静态资源缓存，使得二次访问几乎达到秒开效果。

### 核心代码
```typescript
interface Config {
  apiUrl: string;
  timeout: number;
  retryCount?: number; // 可选的重试次数配置
}
const config: Config = { apiUrl: "/api", timeout: 5000, retryCount: 3 };
```

在此核心配置中，我们严格定义了 `Config` 接口以约束 API 地址与超时时间的类型。通过引入环境变量进行动态配置，实现开发与生产环境的一致性与隔离性。所有涉及网络请求的模块均需读取此配置实例，确保了全局连接逻辑的统一管理。

### 部署步骤
1. **构建镜像**：基于多阶段构建的 Dockerfile，仅将生产依赖打包进最终镜像以减小体积。
2. **推送仓库**：利用 CI/CD 流水线将构建好的镜像自动推送到私有 Harbor 仓库。
3. **滚动更新**：在 Kubernetes 环境中执行 rolling update，确保服务无 downtime 升级。
4. **监控日志**：部署完成后自动校验健康检查接口，并同步推送 Prometheus 监控指标。

- **注意事项A**：部署前务必确认 `.env.production` 文件中的密钥已通过 K8s Secret 注入，严禁硬编码。
- **注意事项B**：每次重大版本更新前，需执行全链路回归测试脚本，确保数据库迁移脚本的正确性。
- **注意事项C**：若出现回滚需求，请优先使用保留的前一个镜像 Tag 进行快速重发操作。

### 团队规范
> 所有代码必须通过严格的代码评审（Code Review）才能合并，评审标准不仅包含逻辑严密性与代码质量，还强制要求单元测试覆盖率不低于 80%，且文档完整性需经过自动化检查工具验证。
